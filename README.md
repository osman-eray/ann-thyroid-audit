# ann-thyroid benchmark audit — code and data

Code accompanying *A Controlled Audit of the ann-thyroid Benchmark*
(Scientific Reports, submission 7c9aaee8-d21e-46eb-9b22-4614badd4bca).

Everything in this repository runs from the raw UCI files. No intermediate artefact is
assumed to exist: `make_dataset.py` rebuilds the working dataset, and every table reported
in the paper is regenerated by a script that verifies its own output.

---

## Environment

The pinned environment, matching Supplementary S7.3:

```
python 3.11.7    scikit-learn 1.3.2    xgboost 2.0.3    imbalanced-learn 0.11.0
shap 0.49.1      numpy 1.26.4          pandas 2.1.4     scipy 1.11.4      matplotlib 3.8.0
```

The scikit-learn pin matters. Version 1.6 removed `SAMME.R` and changed the AdaBoost default
to `SAMME`; on this dataset the two differ by roughly 0.006 ROC-AUC. Every script here sets
`algorithm="SAMME"` explicitly, so results are identical either side of that boundary — but
the other pins are not similarly protected, so use the versions above.

```bash
conda create -n thyroid python=3.11.7 && conda activate thyroid
pip install -r requirements.txt
```

`threadpoolctl` must be 3.1.0 or later. The original analyses used 2.2.0, which crashes on some
Windows installations when scikit-learn's neighbour search requests a thread limit, making every
script involving KNN unrunnable. It manages thread counts only and takes no part in any
computation, so results are unaffected.

`SVC(kernel="linear")` runs with `max_iter=200000` and emits a `ConvergenceWarning` about early
termination. This is expected: the scikit-learn default of unbounded iteration does not terminate
in reasonable time on the SMOTE-resampled folds. The reported linear-SVM results were obtained
under this budget.

## Layout

```
data/      raw UCI files (dataset 102, thyroid-disease directory)
code/      analysis scripts; run from inside this directory
results/   generated tables and figures
CHANGES.md                     what changed in the revision, line by line
DEPOSIT.md                     how this repository was deposited, and the statements for the paper
SUPPLEMENTARY_S7.3_revised.md  corrected environment section for the article
requirements.txt / environment.yml   the pinned environment
```

The working dataset `thyroid_ann_7200.csv` is deliberately **not** committed. Step 0.2 below
regenerates it from the raw files in about a second and records their checksums, so the analysis
chain starts at the archive rather than at a derived artefact.

`data/` holds `ann-train.data` and `ann-test.data` (the benchmark itself), and the sibling
files the audit depends on: `allhypo.data`, `allhypo.test`, `allhypo.names`,
`thyroid0387.data`, `thyroid.theory`, `ann-thyroid.names`.

### Stage 4 — statistical analysis (fast; consumes Stage 2 outputs)

| # | command | needs | answers |
|---|---|---|---|
| 4.1 | `python fs_statistical_tests.py --runs thyroid_fs_comparison_results/fs_comparison_all_runs.csv --out-dir ../results/stats` | 2.6 | R1 major 3, R2 c.3 |

Both run in seconds and refit nothing.

4.1 reports the Wilcoxon resolution floor alongside the post-hoc results. With ten splits the
smallest attainable exact two-sided p-value is 0.00195, which Holm-corrected over 36 pairs
cannot fall below 0.070 — so the Holm-corrected pairwise test is uninformative here by
construction, and the inference rests on the Nemenyi procedure and the equivalence tests.
Do not report "0 of 36 significant" as evidence of absence.

### Stage 5 — the estimator check added in the third revision (fast)

| # | command | produces | answers |
|---|---|---|---|
| 5.1 | `python hfs_discrete_estimation.py` | `discrete_estimation_results/` — four CSVs | R1 third round, condition of acceptance |

`hfs_discrete_estimation.py` runs the selection stage twice on the same folds and the same
seeds: once exactly as released, and once with the binary indicators declared discrete in the
`mutual_info_classif` call, as Equation (2) specifies. Nothing else differs. On a dense array
`discrete_features='auto'` resolves to `False`, so the released run applies the Kraskov
nearest-neighbour estimator — which adds noise to its inputs — to attributes that take two
values. The script writes the selected sets, the hybrid scores, the Table 7 row and the weight
sweep under both settings, and reproduces the deposited values under the released setting.

The four outputs are `hfs_scores_by_mode.csv`, `hfs_selected_by_mode.csv`,
`table7_row_by_mode.csv` and `table9_weight_sweep_by_mode.csv`. Table 9b in the paper is read
off the last two.

## A note on the class names

The benchmark's own documentation, `ann-thyroid.names`, gives neither attribute names nor
class names. The attribute names used throughout this code are recovered from
`allhypo.names`, which describes the same attribute sequence for the sibling files
distributed in the same directory. The sex bit is not documented either: in the distributed
files 0 denotes female and 1 male, which the 5,009 / 2,191 split confirms.

Two artefacts deliberately preserve the original, incorrect class naming:

- `thyroid_ann_7200.csv` carries a `target_label` column reading
  `hyperthyroid` / `subnormal` / `normal`. No script reads it.
- `ablation_all_runs.csv` carries per-class columns named `sens_hyperthyroid`,
  `prauc_subnormal`, `spec_normal` and so on.

Both are retained rather than corrected so that Section 4.1's account of the earlier
designation can be checked against the files themselves. The mapping to the designations
used in the paper is:

| in the files | in the paper |
|---|---|
| `hyperthyroid` (target 1) | overt hypothyroid |
| `subnormal` (target 2) | subclinical hypothyroid |
| `normal` (target 3) | euthyroid |

`perclass_and_dispersion.py` applies this mapping on read.

## Data provenance

The raw files come from UCI dataset 102, the `thyroid-disease` directory of the machine
learning repository. `make_dataset.py` records their SHA-256 digests and refuses to proceed
silently if they differ from the copies this analysis was built on:

The continuous attributes are distributed pre-scaled to [0,1]. The scaling constants are
undocumented; they were recovered empirically and confirmed against the raw values in
`allhypo`, and are applied only where the paper reports clinical units:
age ×100, TSH ×1000, T3 ×100, TT4 ×1000, T4U ×10, FTI ×1000.
